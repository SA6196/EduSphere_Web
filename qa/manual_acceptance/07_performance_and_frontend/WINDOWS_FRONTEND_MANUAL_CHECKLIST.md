# EduSphere — Windows frontend acceptance checklist

Run against the **merged** backend (port 8002) and build generated by `Verify-FrontendBuild.ps1`.
Use only the disposable test accounts, and do not modify older QA quiz visibility unless explicitly testing that fixture and restoring it.

- [ ] `npm ci --no-audit --no-fund` completed without errors (or already verified for this exact checkout).
- [ ] `npm run build` succeeds and `dist/index.html` exists.
- [ ] All six Node/frontend smoke-test scripts pass.
- [ ] `VITE_API_BASE_URL` is set to `http://127.0.0.1:8002/api` for this build.
- [ ] Student login, refresh, logout, and return to login work.
- [ ] Instructor login, question-bank ownership and question list work.
- [ ] Admin login, user/course/offering navigation and permissions work.
- [ ] Student enrollment and available courses screens load without console errors.
- [ ] Attendance pages, semester selection, graphs and prediction load without duplicate requests.
- [ ] Student's marks, semester markbook, and dashboard do not display unpublished QA quiz scores or derivable percentages (e.g. QA quiz `128`).
- [ ] Student direct URL navigation / browser refresh cannot reveal instructor question bank or grading pages.
- [ ] Instructor may open own grading screens; a different instructor cannot view another offering's grading via pasted URL.
- [ ] Student quiz attempt history hides unreleased attempt scores and maximum marks.
- [ ] No answers or `is_correct`, `match_key`, solution fields appear in the student quiz content response in browser Network tools.
- [ ] Failed or timed-out API requests display a useful error without breaking later screens.
- [ ] Repeated clicks while data loads do not create multiple quiz attempts or grading submissions.
- [ ] Browser refresh after logout does not restore protected content.
- [ ] No unexpected red console errors, CORS failures, API HTTP 500, or leaked credential/token values in visible UI.

**Gate:** Every auth, answer-key, mark-release and ownership-related item is critical and must pass. Record any failure with screen, user role, URL path (without credentials), and relevant HTTP code. Never include passwords or JWTs in screenshots or logs.
